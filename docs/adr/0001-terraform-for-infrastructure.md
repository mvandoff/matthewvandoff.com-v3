# Terraform for infrastructure

v3's AWS infrastructure (S3 bucket, CloudFront distribution, GitHub OIDC deploy role, Route 53 records, and later the last.fm fetcher) is defined in Terraform in `infra/`, with state in an S3 backend. AWS CDK was the natural fit, since it's in the same TypeScript as the site. Terraform was chosen partly for its résumé value: it appears in far more job postings and works across clouds. The existing hosted zone, wildcard certificate and GitHub OIDC provider are read with data sources, not imported, so nothing in v3's state can delete or replace them. The OIDC provider is also used by another site's deploy role. The v2 site stays outside Terraform: it was set up by hand and won't change again.
